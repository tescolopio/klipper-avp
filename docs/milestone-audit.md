## Findings to address before stronger prediction claims

1. `AVP_LEVEL` clears `self.points`, but `AVP_CLEARANCE` can then fall back to
   the latest persisted scan. A scan from the previous gantry coordinate frame
   can therefore reappear in an advisory result. Persist and enforce frame
   invalidation across leveling, homing, restarts, and configuration changes.
2. `probe_count()` checks only the newest scan's bounds. It ignores timestamp
   and temperature and does not search older matching records. Clearance's
   persisted fallback does not compare current configured bounds or conditions.
   Define selection and fallback policy explicitly before wiring the new checks.
3. Storage accepts any JSON-serializable metadata shape; consumers assume a
   dictionary. Add versioned metadata validation and tests for malformed rows,
   migration rollback, and legacy records without destroying historical data.
4. `max_surface_z` is an operator-supplied physical assumption. Stopping after
   a measured bound violation cannot undo an earlier unsafe approach. History
   eligibility must not be treated as validation of this setting.

These are code-review findings, not observed hardware incidents. The current
PR leaves adapter, motion planning, configuration, and SQLite schema unchanged.

## This increment: offline foundations

* Add an explicit-clock history context API with configurable maximum age,
  exact bounds matching, temperature tolerance, and actionable rejection codes.
  Invalid/missing conditions and future timestamps fail closed. See
  [history context policy](history-context.md) for scope and usage.
* Add a deterministic JSON baseline generated by
  `python3 -m avp.analytics.baseline`, and run it in CI. Four analytic surfaces
  compare the planned grid against a fixed 9x9 point budget. The output includes
  parameters, schema version, measured-sample envelope and missed reference peak.
* Add 12 tests for boundary conditions, timezone normalization, malformed
  history, SQLite compatibility, deterministic baseline output and offline CLI
  isolation. All original tests continue to run.

## Follow-up milestones in order

1. **Version history and establish provenance.** Add transactional schema
   versioning, stable printer/plate IDs, probe/config fingerprint and frame
   generation. Preserve existing rows as legacy/unknown, with export before
   retention deletion. Acceptance: migration/reopen/rollback tests and explicit
   rejection of unknown provenance for predictions.
2. **Wire context policy into advisory selection.** Expose maximum age and
   temperature tolerance; report selected scan ID, age and rejection reasons.
   Invalidate persisted prediction eligibility when frames change. Acceptance:
   stale/future/temperature/bounds/frame mismatch and restart simulations;
   no rejected history produces an advisory height or lowers motion clearance.
   Specify the fallback grid policy and test it before changing scan behavior.
3. **Record shadow decisions.** Build an opt-in observer that records proposed
   settings, baseline settings and later measured errors while native commands
   remain authoritative. Acceptance: mock assertions of no extra motion or
   command changes, bounded telemetry writes, and fault/restart handling.
4. **Expand benchmarks and integration evidence.** Replay anonymized measured
   meshes with held-out points, thermal changes and narrow defects. Test against
   pinned Klipper versions and capture time/retries/repeatability in a separate,
   explicitly authorized supervised protocol. Acceptance thresholds must be
   agreed before enabling any motion optimization.
5. **Build longitudinal analytics.** Export stable datasets and compute variance
   by plate/material, temperature, soak time, probe and frame. Separate tilt,
   deformation and coordinate changes. Acceptance: analytic fixtures with known
   variance and explicit handling of missing/unequal spatial coverage.
